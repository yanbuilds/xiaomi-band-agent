# Roadmap

## M0：建立真实链路

- [ ] 在 Android 上确认 Band 9 Pro 3.1.175 的型号、地址和认证方式。
- [ ] 评估 `HyperionD/minstall` 的 Android RFCOMM/SPP 连接与 RPK 安装路径；先做认证/设备信息只读验收，再启用 RPK 安装。
- [ ] 用 Gadgetbridge 完成一次今日/历史文件同步（需要解锁手机和真实设备验收）。
- [ ] 保存一份脱敏睡眠原始文件，验证 CRC32、文件 ID 和阶段映射。
- [x] 手机上传事件到本项目 API，Agent/Webhook 回写结构化结果（本地测试完成；真实 bot 地址待配置）。

## M1：手环交互

- [x] 构建最小 Vela RPK：页面、两个按钮、短震动。
- [x] 用公开 Band 9 Pro 实机证据核对 `system.interconnect` 的指纹握手和双向消息；本机 3.1.175 仍需一次最终验收。
- [x] 实现 `question → option_selected → ack`，每个请求带 request_id 和过期时间。
- [x] API 侧幂等保存和失败重试；真实 Android 断线补发仍需设备验收。

## M2：健康同步扩展

- [ ] 接入每日摘要、分钟级心率、血氧和步数。
- [x] API 使用幂等 event_id；Agent runner 失败事件保留并在下一轮重试。
- [ ] 手机本地保存原始文件，服务器只保存用户允许的标准化数据。

## M3：语音可行性

- [ ] 记录一次官方小爱交互的手机端日志和蓝牙包元数据。
- [ ] 判定手环到手机的是音频、识别文本，还是厂商内部命令。
- [x] RPK 已定义 `voice_request` 回传入口；Android 语音服务适配仍需接入具体实现。
- [ ] 任何刷写测试都使用可恢复的备用设备和匹配版本包。

## 验收标准

第一阶段不是“刷机成功”，而是：手环震动并显示问题，用户点击选项，Android 收到一次且仅一次选择，Grok bot 返回确认，手环显示已提交。
