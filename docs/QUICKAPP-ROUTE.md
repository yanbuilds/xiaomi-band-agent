# Band 9 Pro Quick App route

The firmware work exposed a lower-risk path that already reaches the desired
interaction surface: install a Vela Quick App (`.rpk`) on the Chinese Band 9
Pro and use the phone as its only network/BLE owner.

The public `Sany18/smart-band` research repo reports end-to-end Band 9 Pro
hardware tests for `@system.interconnect`, including phone-to-watch messages,
watch-to-phone replies, and the required package fingerprint handshake.  It
also documents that the RPK `META-INF/CERT` generated by the public debug
toolchain is a hash manifest rather than a Xiaomi RSA firmware signature.

This repository now contains a buildable app in `band-app/` and a generated
debug package at `outputs/band9pro-mvp/band-agent-debug.rpk`.  It receives a
JSON question from Android, vibrates, renders up to three choices, sends the
selected option back through interconnect, and shows the Android `ack`.

The current generated artifact is 12,701 bytes with SHA-256
`9ce334f7d1dae19d78cd2efaf602517502da01b4dda13de9e28b102bc315ee51`.
`tools/validate_rpk.py` reports `valid: true`, with `META-INF/CERT` verified as
a file-hash manifest. This is a package-integrity check; it is not evidence
that the n67cn bootloader would accept an AP/OTA image.

## Build

```powershell
cd band-app
npm install
npm run build
```

The output is `band-app/dist/dev.xiaomi.bandagent.debug.0.1.0.rpk`.

## Install with Gadgetbridge

Use a Gadgetbridge build with the Xiaomi RPK/interconnect message bridge,
push the RPK into Gadgetbridge's external files directory, then open it with
the RPK installer.  The phone-side bridge must retain the package fingerprint
announced by the band; inventing a fingerprint causes the app to remain in
`TIMEOUT`.

For a first smoke test, with the phone connected to ADB, use:

```powershell
python tools/send_band_question.py --dry-run `
  --text "是否收到消息？" --option "收到" --option "重试"

python tools/send_band_question.py `
  --text "是否收到消息？" --option "收到" --option "重试"
```

The first command prints the exact broadcast without sending it. The second
asks the patched Gadgetbridge interconnect bridge to deliver it to the RPK.

## Scope

This is an installable app package, not a replacement AP/bootloader image. It
already covers the user-facing Grok interaction without changing signed system
code. Full firmware replacement remains a separate experiment: the extracted
AP/boot images still need a verified updater acceptance test before any real
device flash is safe.
